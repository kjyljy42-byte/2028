# Свадебная хроника · Валерий и Юлия

Полный frontend-прототип свадебного приглашения на React 19 и Vite 7. Мобильная композиция в стиле старинной рукописи: локальные кириллические шрифты, пергамент, орнаменты, авторские SVG-гравюры и все 13 разделов.

## Запуск

Нужен Node.js 20.19+ или 22.12+ (среда проверена на Node.js 24).

```sh
cd /workspace/2028
npm ci --cache /tmp/wedding-npm-cache
npm run dev -- --port 5173
```

На своей машине откройте адрес, который напечатает Vite (обычно `http://localhost:5173`). Это локальный сервер, сайт не опубликован.

```sh
npm run build     # production-сборка в dist/
npm run preview  # локальная проверка собранного сайта
npm test         # дата, RFC 5545 календарь и локальный RSVP
npm run test:e2e # реальные браузерные взаимодействия и адаптивность
```

Браузерные тесты используют `/usr/bin/chromium` в облачной среде. На своей машине задайте `CHROMIUM_PATH` с путём к установленному Chrome/Chromium. Тесты запускают Vite автоматически, если сервер ещё не запущен. Скриншоты тестов пишутся в `/tmp/wedding-*.png`.

## Структура

```text
src/
  App.jsx                  # открытие приглашения, фокус, scroll reveal
  main.jsx                 # точка входа и локальные шрифты
  components/              # заставка, орнаменты, рамки, кнопки, выборы, таймер
  sections/Invitation.jsx  # все 13 разделов и состояние формы
  data/wedding.js          # имена, дата, часовой пояс, место, карта, пути фото
  services/rsvp.js         # заменяемый локальный адаптер RSVP
  utils/                   # отсчёт и генератор .ics
  styles/main.css          # мобильная и настольная композиции
public/assets/             # SVG-иллюстрации и будущие фотографии
tests/                     # unit и браузерные проверки
```

## Замена фотографий

Добавьте настоящие фотографии в `public/assets/`:

| Файл                  | Где появится           |
| --------------------- | ---------------------- |
| `few-horses.jpg`      | Место проведения       |
| `dress-men.jpg`       | Пример для него        |
| `dress-women.jpg`     | Пример для неё         |
| `couple-medieval.jpg` | Финальный портрет пары |

Сейчас вместо них показаны подписанные авторские SVG-заглушки `*-placeholder.svg`. При появлении JPG сайт выберет фотографию автоматически через Vite. Перезапустите сервер после добавления новых файлов; для production выполните сборку заново. При ошибке загрузки фото вернётся соответствующая иллюстрация. Иные имена/форматы можно указать в `wedding.images` в `src/data/wedding.js` (поддерживаются jpg, jpeg, png и webp).

Остальные SVG — временные авторские иллюстрации: замок, принц, принцесса, луна, звёзды, сундук, спальня, карета, меч/щит, пир, бочка. Их можно заменить, сохранив имена в `public/assets/`. Ботанические орнаменты и иконка сайта также локальные.

## Настройки и поведение

Вся информация о свадьбе — `src/data/wedding.js`. Отсчёт идёт до `2028-08-12T13:00:00+03:00` (10:00 UTC). Он обновляется каждую секунду и после даты показывает «Сегодня!». Календарь использует UTC, корректное экранирование и перенос строк по 75 UTF-8 байт; время окончания не выдумывается.

`mapUrl` пока `null`: кнопка карты показывает честное сообщение об уточнении маршрута. Добавьте проверенную HTTPS-ссылку в настройку, чтобы открывать карту в новой вкладке. Studio68 упомянута текстом без выдуманной ссылки.

Заставка использует предоставленное видео `public/assets/opening-story.mp4` (около 4 секунд), а не прежнюю SVG-сцену. На телефоне видео заполняет весь экран через `object-fit: cover` без рамок и текстовых полос; края кадра могут обрезаться под пропорции экрана, центр композиции остаётся видимым. На широком экране применяется `contain`. Исходные 1080×1916 H.264 сохранены без перекодирования, MP4 оптимизирован для быстрого начала загрузки. Воспроизведение однократное, автоматически без звука, с `playsInline` для телефона. В новом ролике нет звуковой дорожки; кнопка звука не отображается (`wedding.opening.hasAudio: false`). После окончания видео пролетает светящийся метеор с мягким хвостом и исчезает за нижним краем экрана; после него остаются монограмма «В & Ю» и надпись «Открыть приглашение». Кнопки пропуска нет. При блокировке autoplay доступно ручное воспроизведение; приглашение открывается после окончания ролика. При ошибке загрузки — статичный постер и доступ к приглашению. В reduced-motion показан только постер, без загрузки видео.

Пути видео и постера указаны в `wedding.opening` в `src/data/wedding.js`. Постер `opening-story-poster.jpg` — последний кадр ролика. После открытия `sessionStorage` предотвращает повтор в той же вкладке; RSVP туда не записывается. Для повторного просмотра удалите ключ `wedding-invitation-opened` в инструментах браузера или откройте новую независимую сессию.

Форма хранит имя, присутствие, ночёвку, трансфер, еду, напитки и собственный напиток. Радиогруппы допускают один вариант, напитки — несколько. При выборе «Другое» требуется описание; при снятии выбора поле и его значение очищаются. Для подтверждения присутствия нужны ответы о ночёвке, трансфере, еде и напитках; для отказа они необязательны. После изменения ответа можно подтвердить его заново.

**RSVP сохраняется только в памяти страницы** через `src/services/rsvp.js`. Обновление страницы удаляет ответы. Нет отправки организаторам, backend, Google Sheets, Supabase, email, внешних RSVP-сервисов или аналитики. Шрифты и иллюстрации не требуют внешних запросов. Для будущего подключения замените реализацию `submitRsvp`, сохранив интерфейс и поля.

Сайт не развёрнут; выполнен только локальный запуск и сборка.

## Живые фоны рукописи

`src/components/JourneyBackdrop.jsx` создаёт непрерывный фон из четырёх сцен: башня, двор, зал и балкон. Иллюстрации находятся в `public/assets/scene-*.svg`. Переходами управляет IntersectionObserver; облака, звёзды и свечи анимируются CSS. Текст интегрирован в фон без заполненных прямоугольных панелей.

## Путь через замок и хранитель даты

Фон теперь один на весь экран: `JourneyBackdrop.jsx` плавно соединяет ночную башню, двор, пиршественный зал и балкон. Белый дракон в `DragonDate.jsx` — авторская SVG-иллюстрация по предоставленному образу, а не анимация фотографии. Нажатие или Enter раскрывает дату; дракон перемещается в угол, сворачивается и продолжает дышать. Дата обновлена на 12 августа 2028, 13:00 МСК, включая календарь и отсчёт. Все движения отключаются при reduced motion.

## Калитка после видео

После нажатия «Открыть приглашение» `GateReveal.jsx` показывает две створки из предоставленного прозрачного PNG и открывает их CSS-поворотом за 3,2 секунды. Фон без встроенных надписей — `public/assets/castle-terrace.webp`, путь задан в `wedding.images.terrace`. Он также используется в начале и финале приглашения. При reduced motion переход занимает 150 мс без калитки. При повторном посещении в той же сессии видео и калитка не повторяются.

Калитка: `public/assets/gate-leaf.png` — исходный PNG пользователя, без перерисовки. Вторая створка отражается CSS. Прозрачные поля обрезаются только при отображении, исходник сохранён целиком. Путь: `wedding.images.gate`.

Калитка открывается на весь viewport поверх уже показанного приглашения. Отдельной фоновой сцены, приветственной надписи и повторного появления главного экрана нет: после открытия удаляется только прозрачный слой со створками. Во время открытия анкета остаётся inert.

## Единый звёздный фон

Основное приглашение использует спокойный тёмно-синий фон с золотыми звёздами по новому референсу пользователя. Изображение: `public/assets/starry-manuscript.webp`, путь `wedding.images.background`. `JourneyBackdrop.jsx` теперь выводит один неподвижный фон без смены архитектурных сцен. Восемь звёзд мягко мерцают через CSS; reduced motion отключает мерцание. Видео и бронзовая калитка сохранены.

Открытие калитки постепенно возвращает яркость и цвет: прозрачные слои `gate-darkness` и `gate-desaturate` исчезают синхронно со створками. Основной экран остаётся на месте. Верхняя строка с монограммой и ссылкой RSVP удалена.

Предварительная загрузка фона и калитки выполняется через `Image()` без вставки картинок в экран видео. Основное приглашение монтируется только при открытии. Глобальное правило `[hidden]` сохраняет скрытие элементов при любых стилях изображений.

Читаемость: основной текст 18–20 px, варианты ответа 17 px, заметки и подписи увеличены, «Листайте вниз» — 19 px. Подпись Few Horses · Подмосковье убрана с первого экрана; название места остаётся в разделе локации. Печать на первом экране заменена на предоставленный прозрачный PNG `public/assets/wax-seal.png`; путь задан в `wedding.images.seal`.

## Видеодракон

`DragonDate.jsx` использует предоставленный ролик, оптимизированный в `public/assets/dragon-departure.mp4`. До нажатия показан первый кадр `dragon-resting.webp`. Видео проигрывается один раз; затем весь слой плавно уходит за левый край и удаляется, открывая дату. Чёрный фон визуально скрывается CSS screen blending, настоящего альфа-канала у MP4 нет. reduced motion сразу открывает дату. Ошибка воспроизведения также открывает дату, не блокируя приглашение. Пути — `wedding.dragon`.

До нажатия используется предоставленный ролик ожидания `dragon-idle.mp4`. Он тихо повторяется только пока дракон виден на экране; уход после нажатия не зацикливается. При reduced motion и блокировке автозапуска остаётся неподвижный постер. Путь — `wedding.dragon.idleVideo`.

Дракон теперь уходит за левую границу viewport, затем сразу запускается `dragon-return.mp4`: он входит слева и ложится под датой. В конце остаётся неподвижный `dragon-settled.webp`. Заголовок «День нашей свадьбы» виден постоянно; дата и время расположены отдельными строками. reduced motion сразу показывает дату и лежащего дракона.

Уход больше не дополняется CSS-сдвигом: используется движение самого ролика. Последняя четверть секунды мягко скрывает остаток хвоста; после ended дата открывается и сразу стартует возвращение. Тонкая вертикальная золотая линия отмечает левый край обоих роликов. После возвращения снова проигрывается idleVideo, с паузой вне экрана и при reduced motion. Метеор на заставке запускается за 1,2 секунды до конца фильма; кнопка по-прежнему доступна после окончания.
